You are helping me build my personal software engineering portfolio website.

Read `CLAUDE.md` first and treat it as the project specification.

## Goal

Build a polished, minimal, technical portfolio website for me as a Master's graduate in Software Engineering.

The website should:
- Present me professionally to recruiters and hiring managers.
- Highlight my technical skills.
- Showcase selected GitHub projects.
- Explain important projects in enough technical depth to demonstrate engineering ability.
- Position relevant experience with C#, .NET, Microsoft Azure, SQL, Docker, cloud/backend development, and related technologies where truthful.
- Eventually be deployable to my own server.

Reference website for visual inspiration:

https://praestholm.dk

Use it as inspiration for the overall minimal/technical aesthetic, but do not copy its design or content.

## Important

Do NOT immediately build the entire website.

We are starting the project from the planning/discovery stage.

First inspect the existing repository and determine:
1. What framework/tooling is already present.
2. What files and structure already exist.
3. Whether anything has already been implemented.
4. What should be kept versus changed.
5. What information/content is currently missing.

Then give me a concise implementation plan for the first milestone.

## First milestone

I want to establish a solid foundation for the portfolio:

- Overall site architecture
- Visual direction
- Responsive layout strategy
- Typography
- Color approach
- Navigation
- Component/page structure
- Project data structure
- Skills data structure

Do not spend time on deployment yet.

Do not invent my projects, work experience, skills, or personal information.

Where information is missing, explicitly mark it as needing input.

## Design goals

The website should feel:

- Minimal
- Technical
- Professional
- Modern
- Personal
- Fast
- Easy to navigate

Avoid:

- Generic developer-template aesthetics
- Excessive animations
- Huge walls of technology logos
- Artificial skill ratings
- Unnecessary visual effects
- Buzzword-heavy copy

## Content structure

The intended homepage is approximately:

Hero
→ About
→ Technical Skills
→ Featured Projects
→ Education
→ Contact

Important projects may later have dedicated pages such as:

`/projects/<project-name>`

Projects should be treated as the centerpiece of the portfolio.

## Project presentation

Each project should eventually be capable of showing:

- Title
- Short description
- Problem/purpose
- Technologies
- Engineering challenges
- Architecture
- Results/outcome
- GitHub link
- Optional live demo
- Optional detailed project page

The portfolio should show what I actually built, not merely list technologies.

## Technology direction

Do not choose a framework blindly.

First inspect the existing project.

If starting from scratch, recommend a suitable stack based on:
- Maintainability
- Performance
- Deployment simplicity
- Developer experience
- Ability to create a polished portfolio
- Relevance to my software engineering profile

We can discuss alternatives before committing.

Act as a senior frontend/software engineer helping me build this project.

When making decisions:
- Explain important trade-offs briefly.
- Prefer simple architecture.
- Avoid unnecessary dependencies.
- Keep the code maintainable.
- Keep accessibility in mind.

For now, do not implement everything.
